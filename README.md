# PDF 翻譯器

只翻譯 PDF 的文字並維持原始版面：譯文寫回原文字的位置，基線、字級、顏色、對齊方式都沿用原文，所有譯文統一使用同一套字型（字型正規化）。圖片、向量圖形、表格框線、連結都不會動到。

## 功能

- **版面保留**：抽出段落後移除原文字形（不加白底），再把譯文排進同一個框。放不下時先等比縮小字級（下限可設定），最後才水平壓縮。
- **動態學習版面規則**：翻譯過程中從文件累積兩條規則，輸出時套用到全文件。
  - 樣式縮放：同一樣式（原字級＋粗細）的文字使用同一縮放比例，取該樣式所有段落中能放進原框的比例的第 20 百分位，因此各頁同類文字大小一致。只有比例更低的離群段落會再個別縮小。
  - 長度比：統計譯文與原文的長度比。預估會超出原框的多行段落，會在翻譯時附上「版面容量（字數上限）」。
  - 精簡：翻完後仍放不下的多行段落，會先請翻譯模型精簡一次，然後才進入檢查。
- **只重新排版，不重新翻譯**：譯文都存在進度檔裡。翻完後如果發現字型、縮放或字距不理想，在「排版 / 字型」分頁改設定，再按「重新排版輸出（不翻譯）」。程式會用新設定重新學習樣式縮放規則並輸出，不呼叫 API。log 會列出有幾段仍需額外縮小或水平壓縮，方便判斷要再怎麼調。暫停中也可以先按這個按鈕預覽新設定，按「繼續」後才會套用到後續翻譯。
- **字型正規化**：預設 Noto Sans CJK TC 常規和粗體，也可以選 Noto Serif CJK TC、微軟正黑體、PyMuPDF 內建字型或自訂字型檔。輸出時會自動做字型子集化，檔案不會變大。
- **行內格式（Markdown 標記）**：段落中的格式以標記送給翻譯模型，譯文要在對應的詞上保留相同標記，排版時再依標記畫回。
  - 允許清單：`**粗體**`、`*斜體*`、`++底線++`、`~~刪除線~~`、`==螢光標記==`、`^上標^`、`~下標~`，其他 Markdown 或 HTML 一律不接受。
  - 整段的粗體或斜體（例如標題）屬於段落屬性，不加標記。
  - 動態規則：每次請求只附上該次段落實際用到的標記規則，沒有格式的批次不附任何規則。頁面上下文與檢查模型只看純文字。
  - 驗證：譯文的標記種類必須和原文相同且成對，不能出現原文沒有的標記。不符時把問題逐段回饋給模型重做一次；仍不符就自動修正（移除多餘標記、補齊跳脫字元），並記在 log。
  - 原文的底線、刪除線線條和螢光筆、底線註解會移除，改畫在譯文對應的詞下。表格框線等其他圖形不受影響：只有整條線都落在文字底下的線才會被當成底線。
  - 斜體以傾斜變形繪製（中文字型沒有斜體字面）；上下標以 65% 字級繪製。
  - 可在「排版 / 字型」分頁關閉。翻譯中不能切換；關閉後重新排版會輸出純文字，原文的線條和註解保留原狀。
- **UI**（tkinter）：可以暫停，暫停後修改模型、思考程度、併發數、批次大小等設定，按「繼續」立即套用。
- **併發翻譯**：可分別設定「同時處理書本數」（批次）、「每本書同時處理頁數」和「每本書最大並發請求數」，暫停後調整、按「繼續」就會生效。
- **批次處理**：在「批次」分頁加入多個檔案或整個資料夾（可含子資料夾），共用同一套設定，可以同時翻譯多本書。每個檔案各自保存進度，停止後再按「開始批次翻譯」會從中斷處繼續。可以指定輸出資料夾、自訂輸出檔名後綴（預設 `_translated`，下方會即時顯示範例檔名）、略過已有輸出檔的檔案，也可以批次重新排版（不呼叫 API）。
  - 暫停、繼續、停止、重新排版輸出都會作用在所有處理中的書上。
  - 任一本書遇到設定錯誤時，整批一起暫停。
  - 進度條和 token 用量顯示整批合計；log 每行會標示 `[序號/總數 檔名]`。
- **中斷恢復**：每段翻譯都即時存進 `work/<檔名>_<hash>_<語言>/state.json`。停止、當機或關閉程式後，再按「開始」會從中斷處繼續。
- **多步驟翻譯檢查**：一頁翻完後，由獨立的檢查模型模糊比對全頁原文和全頁譯文，只檢查有沒有跑題、錯譯、漏譯。檢查模型只回答通過與否，加上被否決的段落區間（標註所屬批次）。被否決的區間會連同全頁原文退回翻譯模型，要求只修復該段，修完再重新檢查，最多重複「最多修復輪數」次。
- **Anthropic 提示快取**：每個請求依穩定程度分層，每層結尾放一個快取斷點：系統提示（整份文件、批次中的每本書共用）→ 整頁原文（同一頁的所有批次、精簡、修復請求共用）→ 該次任務（不快取）。
  - 只在會被重複讀取時才寫入：快取寫入要付 1.25 倍（1 小時 TTL 為 2 倍），讀取約 0.1 倍（Opus 5.5 為 0.05 倍）。所以只有預期有 2 個以上請求共用、或已經在快取中的整頁原文才會標記。只檢查一次的頁面不會寫入快取。
  - 避免平行重複寫入：快取要等寫入它的回應開始串流後才讀得到。同一頁的多個批次會先讓一個請求寫入，其餘等它開始回應後再送出、直接讀取。已確定在快取中的層（依 TTL 追蹤，每次讀取會延長）不會等待；太短而無法快取的層（低於模型最小長度）也不會等待。
  - UI 狀態列與 log 會顯示快取讀取／寫入量，以及依各模型價格算出的輸入成本節省比例。
  - OpenAI 相容服務套用同樣的分層與規則（穩定內容在前、只寫入會被讀回的內容、第一個請求先寫入快取），並依 Base URL 與模型自動選擇做法：

    | 服務 / 模型 | 斷點寫法 | 路由 | 價格（相對一般輸入） |
    |---|---|---|---|
    | OpenAI GPT-5.6 以後 | `prompt_cache_breakpoint` 加上 `prompt_cache_options` 的 explicit 模式（不在每次不同的結尾自動寫入） | `prompt_cache_key`（每頁一個） | 寫入 1.25 倍，讀取 0.1 倍 |
    | OpenAI 較舊模型 | 自動 | `prompt_cache_key` | 寫入免費，讀取 0.1–0.5 倍 |
    | OpenRouter → Claude / Qwen | `cache_control` | `session_id`（整個工作固定在同一供應商） | 依原廠 |
    | OpenRouter → OpenAI GPT-5.6 以後 | `prompt_cache_breakpoint` | `session_id` | 依原廠 |
    | OpenRouter → 其他（Gemini、DeepSeek、Grok…） | 自動 | `session_id` | 依原廠 |
    | DeepSeek | 自動（磁碟快取） | – | 讀取約 0.1 倍 |
    | 其他（vLLM、Ollama…） | 不送任何快取參數 | – | 有回報時才統計 |

  - OpenAI 與 OpenRouter 需要協調快取時會改用串流，等第一個 token 回來就讓其他請求送出。
  - 端點不接受快取參數或串流時，會自動改為不帶這些參數送出，並在 log 提示。
  - OpenAI 相容服務的節省比例依各家公開價格估算，僅供參考。
  - 一個請求涵蓋整頁時（頁面只有一批），不再另外附上整頁原文，因為要翻譯的段落本身就是整頁。只有部分段落的請求（多批次頁面、修復）才附上整頁原文作為上下文。實測同樣 16 頁，翻譯輸入費用少 53%，總費用少 20%。
- **批次模式（Message Batches，半價）**：在「流程 / 併發」分頁把「Anthropic 呼叫方式」設為 `batch`（命令列 `--api batch`），Anthropic 請求就以 Message Batches API 送出，所有 token 都是 5 折。
  - 每一輪（翻譯、精簡、檢查、修復）會把全部頁面的請求合成一批送出，等整批結束後再進行下一輪。結果通常在一小時內回來（最長 24 小時），所以不適合需要即時看到結果的情況。
  - 批次模式下不受「同時處理頁數」和「最大並發請求數」限制，全文件一起排入同一批。
  - 提示快取自動使用 1 小時 TTL，因為批次內的請求順序不固定，處理時間也可能超過 5 分鐘。
  - 不支援伺服器端備援模型（Batches API 不接受 `fallbacks`）。停止工作時會取消尚未完成的批次，未處理的請求不收費；已完成頁面的進度照常保存。
- **模型分開設定**：翻譯和檢查可以使用不同供應商、模型與思考努力程度。
  - `anthropic`：Claude（預設翻譯 `claude-opus-5-5`、檢查 `claude-sonnet-5-5`），思考程度 `low`～`max`。
  - `openai`：任何相容 OpenAI Chat Completions 的服務，填 Base URL 即可（OpenAI、DeepSeek、OpenRouter、本地 vLLM/Ollama 等），思考程度會以 `reasoning_effort` 傳送。

## 安裝

需要 [uv](https://docs.astral.sh/uv/)：

```powershell
# Windows
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

```sh
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

在專案根目錄建立 `.env`：

```
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...        # 可選
DEEPSEEK_API_KEY=...         # 可選；在 UI 的「API Key 環境變數」欄位填 DEEPSEEK_API_KEY
```

## 使用

- Windows：雙擊 `start.bat`
- 其他系統：`./start.sh`
- 或直接執行：`uv run pdf-translator`

第一次執行時 uv 會自動建立虛擬環境並安裝相依套件。

### 命令列模式（不開 UI）

```
uv run python -m pdf_translator.cli 輸入.pdf -o 輸出.pdf --pages 1-5 [--no-check] [--target English]
```

其餘設定會讀取 UI 存下的 `config.json`。

只重新排版已翻好的檔案（不呼叫 API）：

```
uv run python -m pdf_translator.cli 輸入.pdf -o 輸出.pdf --relayout [--font "微軟正黑體"] [--spacing 0.03] [--min-scale 0.6] [--max-scale 1.1]
```

批次處理：輸入可以是多個檔案、資料夾或萬用字元。

```
uv run python -m pdf_translator.cli a.pdf b.pdf 資料夾/ "其他/*.pdf" [--output-dir 輸出資料夾] [-r] [--skip-existing] [--relayout]
    [--suffix 後綴] [-j 同時處理書本數] [--page-concurrency 每本書頁數] [--request-concurrency 每本書請求數]
    [--cache 5m|1h|off] [--api realtime|batch]
```

- `-j` 未指定時使用 `config.json` 的設定（預設 1，也就是一本一本處理）。
- 輸出檔名為 `<原檔名><後綴>.pdf`，預設放在原檔旁邊。同名檔案會自動加上 `_2`、`_3`。
- 後綴預設為 `_translated`。可用 `--suffix` 改，例如 `--suffix _zh` 輸出 `book_zh.pdf`。未指定時使用 UI 存下的設定。
  - 後綴以 `-` 開頭時請寫成 `--suffix=-zh`。
  - 後綴可以空白（`--suffix ""`），但必須同時指定 `--output-dir`。輸出檔永遠不會覆蓋輸入檔。
- `-o` 只能用在單一輸入檔。
- `-r` 會連同子資料夾一起掃描。
- 掃描資料夾或萬用字元時，檔名以目前後綴或 `_translated` 結尾的 PDF 會被視為先前的輸出而略過。直接指定檔名時不會略過。
- `--pages` 會套用到每一個檔案。
- 遇到設定錯誤（例如 API Key）時整批停止；按 Ctrl+C 停止時進度會保存。
- 全部成功時結束碼為 0，任何檔案失敗時為 1。

### OpenAI 相容服務設定範例

| 服務 | Base URL | 模型範例 |
|---|---|---|
| OpenAI | （留空） | 依帳號可用模型 |
| DeepSeek | `https://api.deepseek.com` | `deepseek-chat` |
| OpenRouter | `https://openrouter.ai/api/v1` | `anthropic/claude-sonnet-5-5` |
| Ollama | `http://localhost:11434/v1` | `qwen3` |

如果供應商不支援 `response_format`，請取消勾選「JSON mode」；不支援 `reasoning_effort` 時，思考程度選 `default`。

## 設定重點

| 設定 | 說明 |
|---|---|
| 每批最大字元數 / 段落數 | 一頁內的段落會切成多批送出，每批都附上全頁原文作為上下文（Claude 會快取這部分）。 |
| Anthropic 提示快取 | `5m`（預設）：連續翻譯時最省，每次讀取都會延長。`1h`：經常暫停超過 5 分鐘時使用，寫入較貴（2 倍），但暫停後仍能讀到。`off`：關閉。 |
| Anthropic 呼叫方式 | `realtime`（預設）：串流、即時。`batch`：Message Batches 半價，每輪結果通常一小時內回來。 |
| 同時處理書本數 | 批次時同時翻譯幾本書（PDF 檔），預設 1。和下面兩項分開設定。 |
| 每本書同時處理頁數 / 每本書最大並發請求數 | 每本書各自的上限。批次並行時，總請求數最多為「書本數 × 每本書請求數」。遇到速率限制（429）時先調低書本數；程式會自動退避重試。 |
| 最多修復輪數 | 檢查否決後最多修復幾輪，達上限仍被否決的頁面會記錄在 log。 |
| 最小字級縮放 | 譯文放不下時，字級最多縮到原字級的這個比例。 |
| 最大字級縮放 | 預設 1.0（不放大）。設大於 1 時，較短的譯文可以放大填滿原框，同一樣式仍保持一致。 |
| 字距 | 每個字之間額外的間距，單位 em（字級的倍數），預設 0。負值為緊縮。不為 0 時會逐字繪製，輸出檔約大 2 倍。 |
| 動態學習版面規則 / 精簡過長譯文 | 對應上面兩個機制，可分別關閉。學到的規則會即時顯示在 UI 狀態列。 |
| 保留行內格式 | 以 Markdown 標記保留段落中的粗體、斜體、底線、刪除線、螢光標記、上下標。只影響之後才抽取的頁面；已存進度的頁面維持抽取時的設定。 |
| 額外指示 / 詞彙表 | 會附加在翻譯模型的指示後面，例如專有名詞對照表。 |

遇到 API Key 錯誤、模型名稱錯誤或參數不支援時，工作會**自動暫停**。修正設定後按「繼續」即可。

## 目錄

```
src/pdf_translator/
  app.py         UI
  pipeline.py    工作流程：併發、暫停、中斷恢復、檢查與修復
  batch.py       批次處理：多檔依序執行、輸出路徑規劃
  llm.py         Anthropic / OpenAI 相容 API 呼叫
  prompt_cache.py  Anthropic 提示快取：分層斷點、依需求寫入、避免平行重複寫入的排程
  msgbatch.py    批次模式：把請求收集成 Message Batches 送出並分發結果
  oa_cache.py    OpenAI 相容服務的快取：依服務與模型選擇斷點寫法、路由鍵與價格
  pdf_layout.py  段落抽取與譯文排版（含行內格式的抽取與繪製）
  markup.py      行內格式的 Markdown 標記：允許清單、解析、驗證、動態規則
  config.py      設定與字型
  cli.py         命令列模式
work/            翻譯進度（可刪除）
config.json      UI 設定（自動產生）
```

## 限制

- 只處理有文字層的 PDF。掃描檔需要先做 OCR。
- 直排文字或旋轉的文字保留原文不翻譯。整頁旋轉（/Rotate）的頁面未特別處理。
- 上標會以 `^…^` 保留；但若 PDF 沒有標記上標，字級和位置也和正文差不多，就會被當成一般文字。
- 以填色矩形畫在文字後面的底色（不是螢光筆註解）保留原狀，不會跟著譯文移動，因為無法和表格底色區分。
- 文字顏色仍以段落為單位，段落中個別變色的字會使用段落的主要顏色。
- 段落切分是依版面推測。若某頁切分不理想，可以在 `state.json` 檢查該頁的 `units`。
